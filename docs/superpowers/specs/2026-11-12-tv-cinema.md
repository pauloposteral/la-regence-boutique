## Goal

Make the existing /video presentation more continuous, cinematic, readable and observable without disrupting its current playlist or other commerce pages.

## Approved capabilities

1. Prepare the next eligible native video during current playback; show it only when ready; keep at most two media decks/decoders, including during rapid skips and live reordering.
2. Three per-item transition profiles: clean dissolve 600–800 ms, palette-tinted light 800–1100 ms, subtle depth 800–1000 ms. Default sensible values: 700/950/900 ms. No white flashes, aggressive perspective or permanent overlays. Honor reduced motion. Preserve full clips and end messages. Existing YouTube official UI integration remains provider-controlled.
3. Editable protection metadata for embedded QR, sensitive text and zoom, with safe defaults. Colors amber/ruby/pistachio/cocoa/neutral. Protected content gets stable geometry and no decorative light across the code/text. Do not add duplicate QR to flattened existing media. A future fixed-QR region can be prepared explicitly rather than applied over the current clips.
4. Admin previous/current/next preview and per-item settings, preserving admin gates, upload and reorder behavior. Preview is distinct from live screen telemetry.
5. Source-scoped failure cooldown with independent retry, surviving unrelated polls/reorders. Retain compatible fallback files, source identity, deduplication and cycle continuity. Use actual observed playback and feature detection to reduce effects or select an existing compatible source; do not invent 1080p variants or claim physical TV performance.
6. Secure paired-screen heartbeat with minimal bounded metadata: last seen, actual current and last completed item, progress timestamp, playing/paused/buffering/blocked/error/offline state, resolution, quality mode and playlist revision. Admin-only reads and management; no public arbitrary table writes or reusable privileged secret. Tokens scoped to one device and revocable. Browser status is not proof that a physical TV is powered on.
7. Bounded offline caching of owned direct MP4s plus a valid public playlist snapshot, only with full validated 200 responses, strict allowlist, byte/count limits, Range support, quota/error handling and invalidation when playlist entries are paused/removed while online. Never cache YouTube or Supabase API/auth responses. Preserve a usable cached program on transient network failure. Cache names owned by TV must survive unrelated service-worker cache cleanup.
